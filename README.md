# VYRO

**Facial intelligence, grounded.**

VYRO is a research-preview mobile application for measurement-first facial analysis. It is built around a strict separation between what a camera captures, what a landmark model measures, and what can responsibly be said about those measurements.

> **Status: foundation build.** Camera capture, landmark detection, the measurement engine, and AI explanations are **not implemented**. No scores, measurements, or insights are generated, and no placeholder values are shown.

---

## What this build contains

- A complete Expo Router navigation shell for onboarding, consent, home, scan, insights, profile, analysis, recommendations, progress, and privacy.
- A premium, dark, mobile-first design system with centralized theme tokens and reusable components.
- Explicit consent and local-only preference storage, including versioned consent and one-tap local deletion.
- Typed vision contracts and a fail-closed image-quality gate.
- A candidate measurement catalog that is explicitly exploratory, with no reference ranges or attractiveness claims.
- Typed AI explanation contracts, a backend-proxy-only provider boundary, and structural validation with prohibited-claim checks.
- Optional, lazy Supabase and AI configuration. The app launches and works without any credentials.
- Jest and React Native Testing Library coverage for the quality gate, geometry, consent logic, AI validation, and shared UI.
- EAS build profiles and a documented development roadmap.

## What is intentionally absent

- No camera or photo-library permission request.
- No image capture, upload, or storage.
- No facial landmark model or measurement implementation.
- No attractiveness scores, rankings, percentiles, or leaderboards.
- No genetic, medical, age, ethnicity, or identity inference.
- No paid AI provider integration or API keys in the app.
- No mock analysis data presented as real.

These are product boundaries, not missing polish.

## Quick start

Requirements: **Node.js >= 22.13** and npm.

```bash
npm install
npx expo start
```

The app launches without an `.env` file. To configure optional services:

```bash
copy .env.example .env.local
```

Only `EXPO_PUBLIC_*` variables are exposed to the bundle. They are public, not secret. Provider keys and Supabase service-role keys must never be placed in this app.

### Running on a device

The current build uses Expo Go-compatible modules. When camera, landmark, or other native modules are added, create a development build:

```bash
npx expo run:android
npx expo run:ios
# or in the cloud
npx eas-cli@latest build --profile development
```

Do not create or edit `android/` or `ios/` by hand. They are generated by Continuous Native Generation.

## Navigation map

```
/                     → redirects to /welcome or /home based on consent
/welcome              → product introduction
/consent              → explicit adult + processing consent
/(tabs)/home          → dashboard and status
/(tabs)/scan          → guided capture introduction
/(tabs)/insights      → evidence-first insight model
/(tabs)/profile       → local settings, consent status, deletion
/scan/preparation     → capture checklist
/scan/capture         → capture placeholder (no camera access)
/analysis             → pipeline and hard boundaries
/recommendations      → category and guardrail placeholder
/progress             → longitudinal progress model
/privacy              → plain-language privacy principles
/+not-found           → fallback
```

Tabs are guarded by current consent. The root layout waits for persisted state hydration before hiding the splash screen.

  hooks/               Cross-feature hooks
  store/               Persisted local preferences and consent

Route files should stay thin. Screens live in `src/features/*/screens` and are composed from `src/components/ui`.

## Privacy in one paragraph

VYRO is designed for local-first processing. This build requests no camera or photo permission, collects no images, uploads nothing, and stores only a consent record and app preferences on the device. When capture ships, images and landmarks are intended to remain on-device; only derived measurements may be sent to a backend AI proxy, never images or raw landmarks. Identity recognition, public attractiveness rankings, genetic inference, and medical diagnosis are explicit non-goals. Deleting local data resets consent and preferences immediately.

Read the full model in [docs/PRIVACY_AND_SECURITY.md](docs/PRIVACY_AND_SECURITY.md).

## Testing

```bash
npm test
```

Current coverage focuses on the parts where correctness matters most:

- Quality-gate rejection for dark, blurry, incomplete, and low-landmark captures.
- Session acceptance only when all three angles pass.
- Fail-closed behavior when quality metrics are unavailable.
- Geometry primitives, including zero-denominator handling.
- Consent version, age confirmation, and date validation.
- AI validation: unknown measurements, prohibited claims, confidence/evidence mismatch, and missing limitations.
- Shared button interaction and disabled/loading behavior.

React Native Testing Library 14 uses async `render` and `fireEvent`; tests must await both.

## Limitations

- The analysis engine does not exist. Every analysis-related screen is a clearly labeled placeholder.
- The quality gate is defined and tested, but no frame-quality metrics are computed yet.
- The measurement catalog is exploratory and has no validated reference ranges.
- The AI layer has never been connected to a provider; only contracts and validation exist.
- No accounts, cloud sync, analytics, crash reporting, or push notifications are configured.
- Accessibility has been designed in, but not yet audited on physical devices or with screen readers.
- The app has not been reviewed by a legal, clinical, or ethics professional.
